ARCHER2 Workload Research

An interactive portfolio of my EPCC and Nuffield Research Placement project. Explore workload and node-hour trends for software used on ARCHER2.

Introduction

I developed this web app for users to easily explore job loads and node-hours for the five most-used software applications on ARCHER2 from 2022 to 2026, without requiring any programming knowledge. It combines data analysis with a responsive web interface.


Why ARCHER2 Matters

ARCHER2 is the UK’s national supercomputing service, used by scientists, engineers, and researchers across the country. During my placement at EPCC, I learned how important workload analysis is for understanding how researchers use the machine. Job loads and node-hours reveal seasonal peaks, software demand, and long-term usage patterns. This project helped me see how HPC systems support real scientific work, and why analysing their behaviour matters for planning, scheduling, and future upgrades.

Investigating job loads and seasonal node-hour trends on ARCHER2

I will analyse the five most-used software programs using job volume, node-hours and usage distribution. The project compares seasonal peaks, yearly patterns, individual-year charts, and combined trends across all years.

Research Methods

I investigated job loads and seasonal node-hour trends for the five most-used software applications on ARCHER2 from 2021 to 2026. My research focused on seasonal peaks, yearly patterns, individual-year charts, and combined trends across all years.


Method 1: Python, pandas & matplotlib

Using Python, pandas, and matplotlib in the Anaconda environment, I downloaded CSV files from the ARCHER2 website and combined them into a single dataset. I cleaned the data by removing a.out and overall records, then created new columns for year and month.

I graphed seasonal peaks using line charts for each year and a consolidated graph showing cumulative seasonal usage. I grouped data by season to compare winter, spring, summer, and autumn trends.

For yearly trends, I created bar charts for each year and a cumulative graph using the sum of node-hours for each software application. This helped me identify long-term usage patterns.

I also created graphs showing usage patterns for each software app across each season and across all years combined.


Method 2: Interactive Dashboard

I built a Streamlit dashboard so users can explore the data without programming knowledge. It includes year selection, software‑type selection, and downloadable graphs.


Conclusion

These methods helped me understand job loads and seasonal node-hour trends for the top five software programs on ARCHER2. The visualizations revealed patterns that can support future research and decision-making.
